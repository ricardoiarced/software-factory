## Root cause

Production identity requires `--version` output matching `codex <version>`
(`_codex._VERSION_OUTPUT`, introduced with the deterministic fakes of #31).
Every official Codex release installed on this host — 0.153.4, 0.154.0, and
0.155.1 — reports `codex-cli <version>` instead. The official 0.155.1
artifact therefore cannot satisfy the production identity check as written,
so this rejection is a failed property, not an inconclusive one. Amending
the identity banner is a deliberate production change that needs its own
tests and review, followed by a fresh certification run and a new recorded
decision.

## Decision and scope

The tuple (Codex 0.155.1, official digest `0753dfe1…b761`, Linux, x86_64) is
**unsupported**. `_codex._COMPATIBILITY_SET` stays empty. This decision
covers exactly that tuple on exactly this host identity: it certifies
nothing for any other Codex version or digest, any other Linux architecture,
generic Linux support, or any other operating system. A Linux result never
substitutes for the macOS decision (#45).
