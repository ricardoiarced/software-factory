# Resolve the Codex npm channel through to its vendored platform binary

Factory supports the Codex npm channel by resolving through the npm launcher to the vendored platform binary and admitting that binary directly; Factory never executes the launcher. Resolution triggers only on the launcher's canonical path shape, follows the launcher's own documented layout — the sibling platform package first, then the package-local vendor fallback — and fails closed at every step: an unrecognized shape, a missing vendored binary, or wrong bytes each refuse. The certified permission profile is unchanged: the read root remains the resolved executable's parent directory, which the certified probe already proved sufficient, so the npm channel adds no sandbox width. Run admission observes the install channel from the resolved path and matches the Compatibility Set with that channel dimension included, and the certified environment pins away the launcher's `CODEX_MANAGED_PACKAGE_ROOT` and `CODEX_MANAGED_BY_*` markers.

The grounding is byte identity and environment parity: the npm-vendored binary is byte-identical to the certified github-asset binary of the same release, and the launcher is a pure dispatcher whose added environment markers never appear in the certified github evidence. Per-Run identity therefore digests the exact bytes that execute inside the sandbox, and the npm tuple's manifest anchors that vendored binary per the Candidate Manifest review process.

Amending the permission profile to keep the launcher in the loop was rejected: it widens the certified read, makes Node a Run dependency, and leaves per-Run identity anchored to the launcher rather than to the executed binary. Refusing the channel outright was rejected: it fails the most common install path while the Claude npm channel is supported, and every future npm release would hit the same wall.
