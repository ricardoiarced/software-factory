# Claude Code isolation compatibility for Factory

_Research date: 2026-09-23. Local inspection: Claude Code 2.1.278 on Linux x86_64. No inference Run or sandbox probe was performed._

## Decision

**Do not admit Claude Code Runs yet.** Current Claude Code exposes controls that could plausibly implement Factory's Project Data Isolation and Project Spec Exclusivity, but this exact artifact and host have not passed a real Run probe. In particular, `socat`, a required Linux sandbox dependency, is absent on this host. Factory must refuse this host rather than accept Claude Code's documented default of running commands without sandboxing when the sandbox is unavailable. [Factory contract](../../CONTEXT.md), [Anthropic sandboxing](https://code.claude.com/docs/en/sandboxing)

## Candidate boundary and its limits

| Surface | Candidate control | Evidence and remaining condition |
| --- | --- | --- |
| Bash and child processes | Enable `sandbox.enabled`, `sandbox.failIfUnavailable`, `sandbox.allowUnsandboxedCommands: false`, `sandbox.network.strictAllowlist: true`, and `permissions.blockReadsOutsideWorkingDirectories`; keep `sandbox.filesystem.disabled: false`, `excludedCommands` empty, and network allowlist empty. | The OS sandbox covers Bash, PowerShell, Monitor, and their children. Strict mode disables the `dangerouslyDisableSandbox` retry; `failIfUnavailable` changes startup fallback into failure. The sandbox's read fence and network allowlist need a host probe. [Sandboxing](https://code.claude.com/docs/en/sandboxing) |
| Native Read, Edit, Write, Grep, Glob, NotebookEdit | Use `--restricted` with only the Project Boundary as working directory; test every native file tool for parent and sibling reads and writes, including symlinks. | The Bash sandbox does **not** enclose native file tools. Restricted mode says it confines them to working directories. `Read`/`Edit` path rules are insufficient for arbitrary subprocesses, and `Read` protection for Grep and Glob is described as best effort; NotebookEdit needs its own `Edit` rule. [CLI reference](https://code.claude.com/docs/en/cli-reference), [Permissions](https://code.claude.com/docs/en/permissions), [Sandbox scope](https://code.claude.com/docs/en/sandboxing) |
| Network outside Bash | Remove WebFetch via `--restricted`; exclude MCP, plugins, computer use, cloud sessions, and any other egress-capable tools from the selected `--tools` set. Keep `--strict-mcp-config` with no MCP config. | The sandbox network policy applies to subprocesses, not in-process tools such as WebFetch. Restricted removes WebFetch unless explicitly re-added and refuses cloud sessions. Managed policy and connectors need inspection or a reliable rejection gate. [Sandboxing](https://code.claude.com/docs/en/sandboxing), [CLI reference](https://code.claude.com/docs/en/cli-reference), [Permissions](https://code.claude.com/docs/en/permissions) |
| Project guidance | Combine `--safe-mode` and `--restricted`; inject only Factory's selected `.agent/spec.md` through the Run Request, after Factory's own spec path validation. | Safe mode suppresses CLAUDE.md, skills, plugins, hooks, MCP, custom agents, and auto memory; restricted ignores user, project, and local settings. Bare mode alone is inadequate: it leaves built-in Bash/file tools and explicitly added skill directories active. Claude's documentation does not describe automatic `AGENTS.md` discovery; test parent and project `CLAUDE.md`, `CLAUDE.local.md`, rules, imports, and `AGENTS.md` in the probe. [CLI reference](https://code.claude.com/docs/en/cli-reference), [Memory](https://code.claude.com/docs/en/memory) |
| Managed policy | Inspect the effective managed sources and refuse configurations that introduce hooks, MCP, extensions, extra directories, sandbox exclusions, or broader permissions; ideally reject all managed policy until its effective shape can be proven. | Managed settings outrank `--settings`; safe mode still applies policy hooks and other policy settings. Server-managed policy may be fetched at startup and change over a running session. `claude doctor` lists rejected settings; non-interactive runs can silently skip invalid entries. A pre-Run check of files alone cannot establish effective policy. [Settings](https://code.claude.com/docs/en/settings), [Managed settings](https://code.claude.com/docs/en/managed-settings), [CLI reference](https://code.claude.com/docs/en/cli-reference) |
| Subagents | Exclude Agent from the tool set unless separately probed. | Anthropic says subagents share the parent's sandbox, but their prompts and available tools can differ. [Sandboxing](https://code.claude.com/docs/en/sandboxing), [Permissions](https://code.claude.com/docs/en/permissions) |

The settings above are a **candidate**, not a tested launch recipe. In restricted mode, command tools are removed unless individually named through `--tools`; adding Bash back must be paired with the sandbox and an acceptance probe. `--allowedTools` only preapproves calls; it does not limit which tools exist. `--tools` defines the available built-in set, and `--permission-mode dontAsk` can refuse unapproved calls in a non-interactive Run. Avoid `bypassPermissions`, `--add-dir`, resume/continue, and unsandboxed retries. [CLI reference](https://code.claude.com/docs/en/cli-reference), [Permissions](https://code.claude.com/docs/en/permissions), [Sandboxing](https://code.claude.com/docs/en/sandboxing)

## Certification work before enabling Runs

1. Install the required Linux sandbox dependencies and verify the CLI artifact and host tuple; pin both in Factory's compatibility set. Do not use the version string alone.
2. In an isolated disposable fixture, run actual non-interactive Claude Code inference with the candidate flags. Ask for shell and every available native file tool to read and write inside the selected boundary and across parent, sibling, symlink, and protected-path boundaries. Include direct and indirect subprocess access, network egress, DNS and Unix sockets, and `dangerouslyDisableSandbox` retry attempts. Verify admitted operations succeed and forbidden ones fail.
3. Put conflicting parent/project `CLAUDE.md`, `CLAUDE.local.md`, `.claude/rules`, skills, plugins, MCP, hooks, managed settings, and an `AGENTS.md` sentinel in the fixture. Verify the model receives only Factory's Project Spec as project-specific guidance and no extension gains access. Check behavior when settings are malformed or managed policy changes. [Memory](https://code.claude.com/docs/en/memory), [Settings](https://code.claude.com/docs/en/settings)
4. Test missing `socat`/`bwrap`, failed namespace creation, disabled sandbox, and changed executable as admission failures. Re-run probes for every exact newer stable release and supported host tuple. Anthropic documents an unsandboxed fallback by default, so `failIfUnavailable` must be verified in the real launch path. [Sandboxing](https://code.claude.com/docs/en/sandboxing)

The unresolved design question is how Factory can reliably inspect or exclude effective managed policy **before** submitting a Run Request. If that cannot be proven, an outer process boundary or refusal on managed hosts is required; CLI flags alone do not establish admission. This is an inference from the documented precedence and policy reload behavior, not a tested bypass. [Settings](https://code.claude.com/docs/en/settings), [Managed settings](https://code.claude.com/docs/en/managed-settings)
